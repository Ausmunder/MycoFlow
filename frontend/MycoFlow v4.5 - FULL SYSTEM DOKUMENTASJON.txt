### Database Models (models.py):

**Batch** - Main tracking table
- Fields: id, batch_type, lc_batch, spawn_batch, bag_batch, strain_name
- Dates: lc_dato_inok, spawn_dato_inok, bag_dato_inok, bag_dato_frukting
- Meta: archived, notes, created_at, updated_at

**BatchInfo** - Extended spawn batch info
- Fields: id, spawn_batch (unique), strain_name
- Refrigeration: in_fridge (bool), fridge_start_date (datetime)
- Relationship: units (one-to-many with BatchUnit)
- Calculated: fridge_days, active_days (days excluding fridge time)

**BatchUnit** - Individual spawn units
- Fields: id, batch_info_id (FK), type, substrat, kg, dato_inok, status, used_in_bag
- Contamination: contaminated (bool), contamination_date (datetime)
- Timestamps: created_at, updated_at

**Template** - Reusable configurations
- Fields: id, name, strain_name, units_config (JSON)

### Key Backend Functions:

**calculate_fridge_days(batch_info)**: Returns days spent in fridge
**calculate_active_days(batch_info, units)**: Returns growth days minus fridge days
**get_next_colonization()**: Finds batch closest to 100% colonization (excludes fridged batches)

### 2. Refrigeration Tracking
**Purpose:** Store spawn in fridge to pause mycelium growth

**User flow:**
1. Click spawn_batch ? BatchModal
2. Click "Kjøleskap" toggle button
3. Backend sets in_fridge=true, fridge_start_date=now
4. Days calculation excludes fridge time
5. Badge shows "I kjøleskap" when active

**Backend logic:**
```python
fridge_days = (now - fridge_start_date).days if in_fridge else 0
total_days = (now - earliest_unit_dato_inok).days
active_days = total_days - fridge_days
```

**Research validated:** Spawn at 2-4°C enters dormancy, can be stored months without growth

### 3. Unit-Level Contamination
**Why:** Individual units contaminate, not entire batches

**User flow:**
1. In BatchModal units table, check "Kontam." checkbox
2. Backend sets contaminated=true, contamination_date=now
3. Row background turns red (bg-red-50)
4. Stats calculate contamination rate: contaminated_units / total_units

**Moved from:** Batch.contamination ? BatchUnit.contaminated

### 4. Next Colonization Prediction
**Purpose:** Show which batch will be ready for fruiting soonest

**Algorithm:**
- For each BatchInfo with units:
  - Skip if in_fridge
  - Calculate active_days (excluding fridge time)
  - Assume 30 days for 100% colonization
  - progress = (active_days / 30) * 100
- Return batch with highest progress < 100%

**Dashboard widget shows:**
- Days remaining
- Progress bar
- Expected date
- Spawn batch name, strain, unit count

### 5. Color-Coded Interface

- **Bag cells**: bg-green-50 (green theme)
- **Contaminated units**: bg-red-50
- **Editing cells**: bg-blue-50

### 6. Auto-Save on Blur
**Pattern:** onChange updates local state, onBlur sends API call

**In BatchModal units table:**

## COMMON ISSUES & FIXES

### Issue: "422 Unprocessable Entity" when creating batch
**Cause:** Date format wrong (need ISO with time)
**Fix:** Convert "2025-11-26" ? "2025-11-26T00:00:00Z" via `new Date(date).toISOString()`

### Issue: Backend not rebuilding properly
**Cause:** Docker using cached layers
**Fix:** Use `--no-cache` flag in docker build

### Issue: Frontend shows old version after deploy
**Cause:** Browser cache or old files not deleted
**Fix:** Hard refresh (Ctrl+Shift+R), delete all files before copying new dist

### Issue: "W""" syntax error in main.py
**Cause:** Extra "W" added during nano editing
**Fix:** Line 1 must be `"""` not `W"""`

### Issue: Port 3000 already in use
**Cause:** Old Python server still running
**Fix:** `kill -9 $(lsof -ti:3000)` or use different port (3001)

### Issue: CORS errors in browser
**Cause:** Missing origin in backend CORS config
**Fix:** Add origin to allow_origins list, rebuild backend
